# FRXE 0.6.9 Playlists and Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add FRXE-generated mixes and fully manual local playlists, integrate them into Home/Library/player actions, and finish the FRXE Web 0.6.9 release without allowing Android source sync to overwrite the web version.

**Architecture:** A dedicated pure playlist module owns parsing, mutation, ordering, and generated-playlist construction. `MusicApp.tsx` keeps UI state and persistence wiring, while recommendation data from the previous plan supplies generated mix inputs. Manual and generated data use separate versioned localStorage keys so recommendation refreshes can never mutate user-created playlists.

**Tech Stack:** React 19, localStorage, JavaScript pure data helpers, TypeScript/TSX UI, Node test runner, Playwright, existing source-adapter script.

**Spec:** `docs/superpowers/specs/2026-09-14-frxe-web-0.6.9-design.md`

## Global Constraints

- Manual playlists must never be automatically changed by recommendation refreshes.
- Generated playlists and manual playlists must use separate storage keys and data structures.
- Manual playlists must support create, rename, delete, add/remove tracks, reorder, Play All, and Shuffle.
- Generated playlist types must include Daily Mix, Discovery Mix, Genre Mixes, Artist Mixes, Throwback Mix, Liked Mix, and Fresh Mix when enough source material exists.
- Existing saved-song Library behavior must remain intact.
- FRXE Web version must display `0.6.9` and source adaptation must not rewrite it.
- No account, cloud sync, collaborative playlists, or server-side playlist database in this release.

- [ ] **Step 4: Implement generated playlist rules**

Use deterministic selection and existing recommendation ordering:

- `Daily Mix`: familiar history/library tracks interleaved with recommendation tracks.
- `Discovery Mix`: tracks whose artist is not present in the top familiar-artist set where possible.
- `Liked Mix`: library tracks in saved order, capped at a sensible UI size.
- `Throwback Mix`: older entries from history rather than the newest slice.
- `Fresh Mix`: strongest fresh/discovery recommendation row.
- `Artist Mix · <artist>`: top familiar artist plus recommendation tracks from/around that artist.
- `<Genre> Mix`: recommendation row tagged to that genre.

Use track-ID de-duplication and an artist cap of 3 per generated list. Do not mutate any input arrays.

- [ ] **Step 5: Implement generated cache parsing/signature**

Use `GENERATED_PLAYLISTS_KEY` and accept only arrays of valid generated playlist objects. Signature must change when the ordered history/library IDs or recommendation row IDs materially change.
