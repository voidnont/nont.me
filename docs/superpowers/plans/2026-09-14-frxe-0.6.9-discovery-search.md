# FRXE 0.6.9 Discovery and Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn Home and Search into Spotify-like discovery surfaces that mix familiar artists/tracks with genres and deliberate exploration, while keeping all personalization local to FRXE Web.

**Architecture:** New pure modules classify artists/genres and derive weighted recommendation seeds from existing history/library/search signals. `MusicApp.tsx` orchestrates cached recommendation fetches through the existing `/api/youtube-search` endpoint and renders structured Home/Search sections; core ranking remains in `src/shared/musicSearch.js`.

**Tech Stack:** React 19, TypeScript/TSX UI, JavaScript recommendation helpers, localStorage, existing YouTube search proxy, Node test runner, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-14-frxe-web-0.6.9-design.md`

## Global Constraints

- Personalization must work without an account or cloud database.
- Recommendation weights target roughly 40% played tracks/artists, 25% saved tracks/artists, 20% genre exploration, 15% wildcard discovery.
- Recommendations must de-duplicate tracks, limit artist domination, and cache results locally.
- Cold-start users must still receive broad discovery.
- Search must preserve Songs as the baseline result section even when artist/genre classification is weak.
- Existing official/topic/VEVO ranking in `src/shared/musicSearch.js` must remain the song ranking baseline.
- Recommendation/search failures must not break playback, Save, or Library.
